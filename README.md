## 功能地图

- **今日页**：hero（摄入/消耗/缺口环形图+目标评价徽章）→ 今日配额卡（日类型 segmented + 力量日训练时段开关 + 碳蛋脂进度条 + 力量/有氧日的碳水补偿提示条）→ 饮食记录（四餐，每餐显示 实际/配额 碳蛋脂；≥2项时可"存为套餐"）→ 补剂打卡
- **日期系统**：hero 标题两侧 ‹› 逐天切换；点标题开日历弹层（月视图，绿/蓝/紫点=饮食/训练/补剂，可跳任意历史日期补记）；未来日期禁止
- **训练页**：训练日 segmented 由用户方案（`D.split`）生成 + 有氧（9种，MET估算消耗）；灰字带出上次数据，"沿用上次"一键填充；「管理动作」进入动作库编辑模式（↑↓排序/删除/添加）；历史记录点击进编辑面板（力量：单动作数值修改/删除、改时长重算消耗；有氧：改类型/时长）
- **趋势页**：体重平滑曲线（整数刻度）+ 近14天缺口柱状图（无记录日灰色占位）+ 两周复盘卡（v2.4 自动建议状态条 + 规则）
- **AI 页（v2.6）**：对话式操作台。文字/图片/语音输入 → 对话模型输出 `{reply, actions[]}` 协议 JSON → app 校验后渲染成精美动作卡（训练/饮食/入库/套餐/动作库/体重）→ 点确认执行并同步。信息不足时模型先追问（actions 为空），凑齐再出卡。快捷按钮：今日回顾/本周回顾（app 先算好统计数字注入，模型只解读不重算）。聊天记录仅本地（不进同步仓库），上限 60 条
- **AI 动作协议**：log_strength / log_cardio / log_food（追加；新食物带 lib 单份基准自动入库为 AI估算）/ **set_meal（整餐替换，修改/删除某餐必须走它，v2.6.1 修复：此前模型会假装删除实际追加）** / add_food（自建）/ save_combo / add_exercise / remove_exercise / log_weight；记录类动作可带 `date` 补记历史（v2.7.4，默认真实今天）；训练记录不可通过对话改删（提示词边界，引导去训练页编辑）；app 侧白名单校验（重量<500kg、单项<1000g碳水等），非法动作丢弃；JSON 解析失败自动带修复提示重试一次
- **设置页**：身体档案（含性别/目标下拉，BMI/BMR/日常消耗三卡+方案说明）、训练方案（三/四/五分化预置一键切换 + 训练日增删改名，支持不练腿等自定义）、GitHub 同步、AI 模型配置三插槽（①对话=DeepSeek ②视觉=拍照识别选配 ③语音=ASR选配，均 OpenAI 兼容格式，换 key 即用；视觉/语音未配置时对应按钮自动隐藏）、导入导出

## 核心口径（生产逻辑，改动需 Joe 同意）

**配额引擎**（g/kg 体系，源自 `04-饮食管理/饮食原则.md` 和 `05-指导纲要/`）：

| 目标 | 蛋白 | 脂肪(男/女) | 碳水 训练日/休息日 |
|---|---|---|---|
| 减脂 cut | 1.6 | 0.8 / 1.0 | BMI≥28: **2.7/2.0**（Joe 当前）；BMI<28: 3.0/2.5 |
| 塑形 recomp | 1.6 | 0.8 / 1.0 | 3.5/2.5 |
| 增肌 bulk | 1.8 | 0.8 / 1.0 | 4.0/3.0 |

- 有氧日碳水 = 休息日基础 + 当日有氧kcal÷4；**力量日碳水 = 训练日基础 + 当日有氧kcal÷4**（v2.5，依据饮食原则"额外运动消耗=额外补充碳水"，力量+有氧同日不再漏补）；力量/有氧记录会自动改日类型，力量优先
- 球类运动日口径（Joe 2026-08-02 已裁决）：维持有氧日基数180g+补偿，不采用文档的243g训练日基数（243g为2h足球场景设计，套1h网球会把缺口压到9%拖慢减脂；kcal÷4补偿已随时长强度自适应）。若恢复长时间球类运动再议"高强度球类"标记
- 分餐比例（力量日晚练）：碳水 20/20/20/40%（早/午/训前/练后餐），上午练则午餐为练后餐；休息日三餐均分
- BMR：默认 Mifflin-St Jeor；填体脂率则 Katch-McArdle。消耗 = BMR×活动系数 + 训练kcal（力量 MET 4.5）
- 缺口健康区间（goalBand）：cut [10,22]%，recomp [-5,8]%，bulk [-15,-5]%（负=盈余），hero徽章/柱状图配色/图例都按此
- **两周调整规则是手动的**：降幅<1.5kg 碳水减27g/天（下限2.0g/kg）

## 数据与同步

- **配置保留（v2.8.2）**：三组AI模型和GitHub设置独立保存至`ht_settings_v1`及`ht_settings_backup_v1`，应用更新不改这两个键。启动时保留当前配置，仅从旧本机备份补回完全缺失的配置组；不向新配置混入旧密钥。普通保存保护另一标签页更新的配置，后台同步只用已保存配置。用户主动保存修改/清空仍生效。本机副本不能覆盖清除全部网站数据或换设备场景。
- localStorage优先（key `ht_data_v1`；当前数据结构`ver:6`），GitHub为可选同步层。旧版首次升级前将原JSON原样保存在`ht_backup_before_v6`；备份失败或本地JSON损坏时停止升级，不覆盖原数据。
- 同步：GET contents（no-store）拉远端 → mergeData合并 → 内容改变才PUT；并发加锁及409重拉重推。每次记录后3秒防抖；启动、回到前台、联网恢复时同步，前台未编辑时每30秒检查。设置页显示持续状态/错误，不覆盖未完成的表单。
- merge策略：仅浏览生成的空白日updatedAt=0，只有真实编辑产生时间；有同步基线时按餐次、训练、补剂打卡等合并独立修改，同项冲突按时间取新并提示；无基线旧日按updatedAt取新；无mealCleared标记的空餐次不能清除已有饮食，冲突保留双方原件。真实编辑清空餐次时写入标记。落选完整日快照写入dayHistory。weights按日期及更新时间合并；pending仅保留实际餐次引用；split按splitUpd取新。导入失败回滚，非法远端JSON不推送。本机syncBaseDays及lastSync不上传。
- **删除与恢复（v2.8.0）**：食物、套餐的删除、修正和冲突覆盖先保留完整条目至`libraryTrash`，可在食物面板“回收站”恢复。合并比较`max(updatedAt,ts)`，同时间冲突稳定选取并保留另一份；恢复/新增产生晚于所有已知标记的新时间。旧removedFoods/removedCombos仅作删除兼容元数据，不再强制补回白名单。旧文件仍保存的活跃条目在首次升级/导入时优先保留。
- **待估算闭环**：库里没有的食物记 pending → 同步进仓库 → 电脑端 Claude 读 `pending` 数组，按名字估算碳蛋脂追加进 `foods`（`{name,cat:"AI估算",serv,servG:估算每份克重,c,p,f,ts:当前毫秒时间戳}`，name 必须与 pending 完全一致，servG 尽量给估算值以支持按克记录；外卖按重油重调味口径，宁可高估）→ app 下次同步自动回填当天记录并清队列
- 食物校准使用update_food；AI先读取完整份量与营养基准，已有食物按明确克重/份数在本地计算，连续修改库和重算餐次按顺序预览。delete_food移入回收站，历史餐次不删除。确认前状态变化会重算卡片并要求再次核对。
- 模型密钥、GitHub令牌和聊天只在本机保留，不进入普通导出/同步。导入文件不覆盖本机凭据；新设备需自行配置密钥。旧备份仍原样保留，不能误称历史Git中的密钥已撤销。
- 多用户：共用 friends-data 仓库 + 各自文件名；token 为 fine-grained、仅限对应仓库 Contents 读写

## 食物库

**品牌与名称复用（v2.8.1）**：先匹配同品牌同规格条目；品牌/店名仅描述来源时，按同种通用食品匹配已有库名，is_new=false，使用库内营养基准；普通新食品默认用通用名。全脂/脱脂、含糖/无糖、拿铁/黑咖啡等实质差别保留，歧义时追问。这里只调整模型提示词，不自动重命名、合并或删除库中已有条目。

**v2.8.0保留已保存库**：不再执行清零重建。旧食物基准、用户标记、上次用量、套餐及自定义方案保留；空库也保持为空，不因重载补默认食物。只有全新浏览器首次初始化使用少量原默认条目。SEED_FOODS不作为当前迁移输入。

套餐（`D.combos`）：一餐≥2项可保存，出现在“常用”和“套餐”；复用逐项展开，删除进入回收站。套餐和历史餐次采用保存时快照，后续食物库更新不追改历史；如需改当天餐次，明确使用set_meal。

## 训练方案（v2.5 起用户可配置）

`D.split` 数组驱动，预置三分化（推/拉/腿）、四分化（胸/肩/背/腿，默认，与 `03-健身计划/当前计划.md` v4 一致）、五分化（胸/背/肩/腿/手臂）；设置页可切换预置、增删/改名训练日（支持不练腿等）；训练页「管理动作」增删/排序动作库。历史记录存 day key + 名字快照，改方案不影响历史。
